# 桌面快捷方式自动收纳设计

## 背景与目标

Windows 安装或更新软件时经常在桌面创建 `.lnk` 快捷方式。FeatherFences 应在运行期间检测这些新增快捷方式，等待文件写入稳定后，将其自动移动到最适合存放快捷方式的用户收纳箱。

本功能只处理程序启动后新增或通过重命名生成的桌面快捷方式，不追溯整理启动前已经存在的快捷方式。它始终启用，且不受“下载接管”开关影响。

## 范围

候选目标仅包括用户通过“新建收纳栅栏”创建的收纳箱。以下栅栏不参与选择：

- 绑定任意目录的文件夹栅栏；
- 专用下载收纳箱；
- 已删除或失效的栅栏。

如果没有用户收纳箱，新增快捷方式保留在桌面。之后新建收纳箱时，不对这些旧快捷方式进行追溯移动。

## 栅栏类型与配置迁移

为 `FenceCfg` 增加持久化的显式类型，至少区分：

- `Collection`：用户收纳箱；
- `Portal`：文件夹栅栏；
- `Download`：专用下载收纳箱。

新建栅栏时直接写入对应类型，业务逻辑不再依赖标题或目录名称判断类型。

加载缺少类型字段的旧配置时执行一次兼容迁移：

1. `id` 等于 `download_box_id` 的栅栏标记为 `Download`；
2. 旧式 `folder == None` 的收纳栅栏标记为 `Collection`；
3. 目录直接位于 `%APPDATA%\feather-fences\boxes\` 下、且不是下载箱的栅栏标记为 `Collection`；
4. 其他栅栏标记为 `Portal`。

迁移结果随下一次正常配置保存写回磁盘。旧配置已有的布局、透明度、图标尺寸和目录均保持不变。

## 桌面事件与稳定性检查

复用现有桌面 `ReadDirectoryChangesW` 监听器和主线程接收通道，同时覆盖当前用户桌面与安装器常用的公共桌面。监听线程只投递完整路径，不进行文件移动或收纳箱扫描。

主线程接收事件后：

1. 将扩展名不区分大小写为 `.lnk` 的路径加入待处理集合；
2. 同一路径的重复新增、修改或重命名通知合并为一个候选项；
3. 定时读取文件长度和修改时间；
4. 连续两次约一秒间隔的检查均未变化后，才尝试自动收纳。

候选路径消失、变成目录或不再是 `.lnk` 时，从待处理集合移除。暂时被安装程序占用而移动失败时保留候选，后续定时重试。

## 收纳箱统计

每次处理一个稳定快捷方式时，扫描所有有效用户收纳箱的顶层目录。只统计实际文件：

- `.lnk` 文件计入快捷方式数；
- 其他文件计入普通文件数；
- 子文件夹和无法读取的目录项不参与统计。

快捷方式占比定义为：

`快捷方式数 / (快捷方式数 + 普通文件数)`

比例比较使用整数交叉相乘，避免浮点精度和除零问题。

## 目标选择规则

选择过程必须具有确定性：

1. 如果所有候选箱的快捷方式数均为零，则优先选择空箱；
2. 否则选择快捷方式占比最高的收纳箱；
3. 占比相同，选择快捷方式数量更多的收纳箱；
4. 仍然相同，选择栅栏 ID 较小的收纳箱。

“空箱”指快捷方式数和普通文件数都为零。若所有箱子都没有快捷方式且不存在空箱，则所有箱子的占比及快捷方式数相同，最终按栅栏 ID 选择。

## 移动、刷新与错误处理

文件移动复用现有 `watcher::move_to_dir`：

- 自动创建不存在的目标目录；
- 同名文件存在时生成 `名称 (1).lnk` 等唯一名称；
- 支持同卷重命名及跨卷复制后删除。

成功移动后：

- 从待处理集合移除源路径；
- 立即刷新并重绘目标收纳箱；
- 重新维护桌面图标禁放区。

无法枚举某个收纳箱时跳过该箱，不阻塞其他候选箱。若本次没有任何可统计的有效收纳箱，快捷方式留在桌面并结束该候选项，避免日后创建收纳箱时发生追溯移动。

## 组件边界

- `config.rs`：定义栅栏类型并负责旧配置迁移。
- `main.rs`：接收桌面事件、维护快捷方式候选状态、选择目标、驱动移动与刷新。
- 独立的纯函数：完成文件分类、收纳箱统计和候选排序，便于单元测试且不依赖 Win32 窗口状态。
- `watcher.rs`：继续只负责目录事件监听和通用文件移动，不加入业务选择规则。

## 测试与验收

单元测试覆盖：

- 缺少类型字段的旧配置迁移，包括下载箱、旧式无目录收纳箱、`boxes` 下的收纳箱和普通文件夹栅栏；
- `.lnk` 大小写识别、普通文件识别及文件夹忽略；
- 所有箱子无快捷方式时的空箱优先；
- 快捷方式占比最高者优先；
- 占比相同时快捷方式数量更多者优先；
- 前述条件完全相同时按较小 ID 选择；
- 没有用户收纳箱时不选择目标；
- 重复桌面通知不会产生重复候选。

实现完成后运行 `cargo fmt --check`、`cargo test` 和 `cargo check`。手工验收时，在程序启动后向桌面创建或复制 `.lnk`，验证其等待稳定后进入预期用户收纳箱，同时确认下载箱和文件夹栅栏从不被选中。

## 非目标

本次不增加设置开关、托盘菜单或可视化提示；不自动整理普通文件、子文件夹、URL 快捷方式或启动前已存在的桌面内容；不递归统计收纳箱子目录。
